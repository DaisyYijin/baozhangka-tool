# 自动化点击工具 设计方案

> 类"按键精灵"的鼠标 / 键盘自动化工具 —— 可视化编排动作序列、循环执行、全局热键启停。
> 硬性指标:**Windows XP 起步全兼容、ARM Linux 原生运行、零额外安装依赖、单文件免安装**。

- 文档版本:v2.0(2026-11-07)
- 代码基线:本仓库 v1.5.0(HEAD:`cffa77b`)
- 相关文档:[README.md](../README.md)(用户手册)、[GLOSSARY.md](GLOSSARY.md)(术语)

## 2. 技术选型论证

**结论:纯 C99,每平台只使用操作系统自带的系统库。**

| 备选 | 否决原因 |
|------|----------|
| Go | Go 1.11 起停止支持 Windows XP/Vista,现代工具链无法产出 XP 二进制 |
| Python / Lua 等解释型 | 目标机需预装运行时,直接违反"零依赖" |
| Rust | XP target(三级支持)需特定 toolchain 链,且无 cargo 的环境无法自助构建 |
| Electron / .NET / Java | 体积大且均需运行时,XP 兼容性差或不存在 |
| AutoHotkey | 仅 Windows,闭源,无法满足 Linux/ARM |

C99 + 系统 API 的依赖面:

| 平台 | 依赖库 | 说明 |
|------|--------|------|
| Windows(x86,32 位) | kernel32 / user32 / gdi32 / comctl32 / comdlg32 / shell32 / imm32 / msvcrt | **全部为 XP SP3 自带**;`-static` 静态链接 CRT,产出单 exe(约 440KB) |
| Linux(x86_64 / arm64 / armhf) | libX11 + libXtst(+ libc / libm) | 任何 X11 桌面(含树莓派官方系统)**必带**,无需安装;构建用 gcc + pkg-config |

> "零依赖"定义:目标机**开箱即有**图形会话的前提下,不安装任何软件包。libX11/libXtst 是 X11 桌面的组成部分——没有它们就没有桌面,GUI 程序无从运行。GTK3 及其依赖链(glib/pango/cairo/dbus 等 100+ 包)不属于此列,故移除。

## 3. 总体架构

三层结构,核心与平台彻底解耦(自 v1.0 起保持,是双端共享一套逻辑的基础):

```
┌────────────────────────────────────────────────────────────┐
│  GUI 层(每平台原生,互不共享)                              │
│  Windows: src/win/gui.c + dlg_edit.c + picker.c (Win32)    │
│  Linux  : src/linux/main.c + xui.c (纯 Xlib 手绘) ← M1 迁移 │
├────────────────────────────────────────────────────────────┤
│  核心层(平台无关,纯 C,双端共用 → src/core/)              │
│  engine.c  执行引擎/任务簿/循环/跳转/子流程调用            │
│  ac_defs.h 数据模型: Step / Task / TaskBook                │
│  ac_keys.c 统一键码表(Win VK ↔ X11 keysym 单一映射)       │
│  import.c  任务 CSV 存取 + Excel↔步骤互导                 │
│  sheet.c/zip.c/inflate.c 内置 xlsx 解析(自实现,零依赖)   │
│  u8.c      UTF-8/UTF-16 转换(全链路 wchar_t)              │
├────────────────────────────────────────────────────────────┤
│  平台抽象层(Platform 函数指针,ac_defs.h 定义)            │
│  mouse_move/down/up/scroll · key_combo · text_paste        │
│  sleep_ms(可中断) · rand · get_pixel · find_window        │
│  ocr_region · *stop(停止标志)                             │
├────────────────────────────────────────────────────────────┤
│  平台实现                                                  │
│  Windows: src/win/platform_win.c  (SendInput/剪贴板/热键)  │
│  Linux  : src/linux/platform_x11.c (XTest/XGrabKey/XImage) │
└────────────────────────────────────────────────────────────┘
```

要点:

- **执行线程模型**:GUI 主线程 + 一个执行线程;停止通过共享 `volatile int *stop` 标志,`sleep_ms` 分片睡眠(每 10~20ms 查一次),保证热键停止在当前动作内即时生效,不需强杀线程。
- **键码统一**:`ac_keys.c` 以"逻辑键名"(`ctrl`、`f5`、`enter`…)为中枢,Win 端译成 VK,X11 端译成 keysym,任务文件跨平台通用。
- **文本全 wchar_t**:核心与 GUI 之间只传宽字符,编码转换收口在 `u8.c`(Linux 文件名 UTF-8)与 Win32 API 边界。

## 4. 动作与任务模型

### 4.1 动作类型(v1.5.0 已全部实现)

| 动作 | 说明 |
|------|------|
| 单击 / 双击 / 多击 / 右击 / 中击 | 坐标可设 w,h → 非零则在区域内**随机落点** |
| 输入 | 中文文本(剪贴板粘贴,任意程序可用);可"先清空"(自动 Ctrl+A→删除) |
| 按键 / 组合键 | `ctrl+s`、`alt+tab`、`win+r`、`F5`…最多 8 键 |
| 等待 / 滚轮 / 拖动 | 等待=纯延时;滚轮正=向上;拖动=起点→终点平滑 |
| 跳转 | 跳到指定步骤 / 指定 TAB(构成循环、分支) |
| 等窗口 | 等标题包含某文本的窗口出现(比固定延时可靠),超时可设 |
| 判断 | 屏幕取色与目标色比对(逐通道容差),满足则跳转 → 实现条件分支 |
| 调用 | 子流程:执行另一 TAB 后返回调用处,最多 8 层嵌套 |
| 读文本(OCR) | 区域文字识别(内置轻量模板匹配,数字/字母/常用符号),关键词命中可跳转 |

任务级设置:循环次数(0=无限)/ 循环间隔 / 延时随机抖动(拟人化)/ 开始倒计时 / 循环次数跟随 Excel 行数 / 每 TAB 独立数据源。

### 4.2 任务文件 = 标准 CSV(Excel 可直接编辑)

真实示例(`examples/示例任务.csv`):

```csv
#设置,循环次数,2,循环间隔毫秒,500,随机抖动毫秒,50,开始倒计时毫秒,3000
动作,X,Y,次数,间隔毫秒,文本或按键,前延时毫秒,后延时毫秒,输入前清空,启用,备注
单击,100,200,1,0,,0,200,,是,"示例:点击(100,200)"
双击,300,400,1,0,,0,200,,是,示例:双击
多击,500,300,5,300,,0,200,,是,示例:连点5次每次间隔300ms
输入,0,0,,,"你好,世界",0,300,是,是,示例:先清空再输入中文
```

Excel 导入:`.xlsx` / `.csv` → 一键生成步骤;输入文本支持 `{列名}`/`{列N}`/`{行}` 占位符逐轮替换。xlsx 解析(zip + DEFLATE)为自实现,无任何第三方库。

## 5. Windows 后端(XP 兼容要点)

编译(见 `build/windows_build.bat`,MSYS2 MinGW-w64 i686):

```
gcc -std=c99 -O2 -municode -mwindows -DUNICODE -static \
    -Wl,--subsystem,windows:5.01 -Wl,--major-os-version=5 -Wl,--minor-os-version=1 \
    -lcomctl32 -lcomdlg32 -lgdi32 -luser32 -lshell32 -limm32
```

XP 兼容约束(长期遵守的**硬规则**):

1. **32 位**:只发布 x86 版(64 位系统原生兼容运行;XP x64 不在支持范围)。
2. **子系统 5.01**:PE 头声明最低系统 XP SP3 之前即拒绝启动的门槛必须保持。
3. **静态链接 CRT**:`-static`,不携带任何可再发行运行库。
4. **API 白名单**:仅用 XP 自带的上述 DLL 导出。输入注入用 `SendInput`(XP 已有),全局热键 `RegisterHotKey`,视觉样式经 `app.manifest` 启用 comctl32 v6(XP 支持)。
5. 新增 API 前先查 XP 导出表;Vista+ 才有的 API(如 `GetTickCount64`)禁止直连,需要时运行时 `GetProcAddress` 探测并降级(退回 `GetTickCount` 等 XP 等价物)。

> XP 无 UIPI(那是 Vista 引入),因此 XP/Win7~10 上向提权窗口注入**无需**管理员权限;Win11 少数提权场景按需"以管理员运行"。

## 6. Linux 后端(ARM + 零依赖)

### 6.1 输入与系统能力(已实现,保留)

| 能力 | 实现 |
|------|------|
| 鼠标移动 / 点击 / 滚轮 / 拖动 | `XWarpPointer` + `XTestFakeButtonEvent`(libXtst) |
| 键盘 / 组合键 | `XTestFakeKeyEvent` + `XKeysymToKeycode` |
| 全局热键(F6 开始 / Ctrl+F12 停止) | `XGrabKey` 抓根窗口键 |
| 取色(判断动作) | `XGetImage` 读单像素 |
| 等窗口 | `XQueryTree` 遍历 + `XGetWMName` 标题匹配 |
| 中文输入 | 剪贴板 + XTest 发 Ctrl+V(见 6.3) |

### 6.2 GUI:GTK3 → 纯 Xlib 手绘(本方案核心改造)

**现状**:`src/gtk/main.c` 用 GTK3,是 Linux 端唯一违反"零依赖"之处。
**目标**:新建轻量控件层 `xui.c`(仅依赖 libX11),界面与 Windows 版同构(任务列表 + 参数区 + 开始/停止 + 状态栏)。

设计要点:

- **控件 = X 子窗口**:`XCreateWindow` 创建按钮 / 输入框 / 列表 / TAB 页子窗口,事件(ButtonPress / KeyPress / Expose)由 X 服务器天然路由,不必自写命中测试;Expose 时自绘(3D 边框 + 文字),观感为经典灰底风格,不追求主题化。
- **中文显示**:`XCreateFontSet` + `XmbDrawString`(Xlib 内置 i18n,经 XLOCALE 解析,无需 Xft/freetype)。字体集 fallback 到 `-misc-*` 系列保证任何系统可显示。
- **事件循环统一**:主循环 `XNextEvent` 一并处理控件事件与 `XGrabKey` 的 KeyPress → 现有的 `x11_hotkey_poll()` 轮询**退役**,热键从"轮询"升级为"事件驱动"(响应更快、空转更少)。
- **列表控件**:自绘行(启用勾选 / 动作类型 / 坐标 / 备注),支持滚动与双击编辑;布局参数尽量与 `src/win/gui.c` 共享常量,降低双端视觉分叉。
- **取点覆盖窗**:`override-redirect` 全屏窗 + `XShape` 半透明十字线,等价 Windows 版 `picker.c`。
- **目录重命名**:`src/gtk/` → `src/linux/`(名实相符,迁移一并完成)。

### 6.3 剪贴板(去 GTK 后需自实现)

粘贴输入中文必须有"把文本交给目标程序"的通道。GTK 退役后自实现 ICCCM selection owner(约 150 行):

1. 置文本时 `XSetSelectionOwner` 同时持有 `XA_PRIMARY`、`CLIPBOARD`、`UTF8_STRING`;
2. 主循环响应 `SelectionRequest`:`XChangeProperty` 回写,支持目标格式 `UTF8_STRING` / `text/plain;charset=utf-8` / `COMPOUND_TEXT` / `XA_STRING`;
3. 随后 XTest 发 `Ctrl+V`,目标程序前来取数据即完成输入。

已识别风险:请求发生在我们发出 Ctrl+V 之后,期间主循环必须持续处理事件(执行线程注入后由主线程代答 selection 请求——用 20ms 定时唤醒即可,粘贴窗口极短)。

### 6.4 ARM 构建

`build/linux_build.sh` 与架构无关(gcc + pkg-config),CI(`.github/workflows/release.yml`)矩阵:

| 产物 | 架构 | 构建方式 |
|------|------|----------|
| `linux-x86_64` | AMD64 | x86 容器 |
| `linux-arm64` | aarch64(树莓派 4/5、国产 ARM 平台) | arm64 容器 |
| `linux-armhf` | armv7(树莓派 3 等) | `run-on-arch-action` QEMU |

M1 完成后脚本中 `gtk+-3.0` 依赖删除,仅留 `x11 xtst`。

## 10. 风险与限制

| 风险/限制 | 说明与对策 |
|-----------|-----------|
| Wayland 原生会话 | XTest 无法注入原生 Wayland 应用;XWayland 会话可用。README 已注明选 X11 会话,长期看需评估 uinput 路线(需权限,列为后续) |
| 仅 32 位 Windows 版 | XP x64(罕见)不支持;64 位 Win 原生兼容 32 位 exe,不影响 |
| selection 粘贴竞态 | §6.3;若极端场景失败,退化方案:仅支持 ASCII 逐键注入(XTest keysym),中文仍走剪贴板 |
| OCR 能力有限 | 模板匹配仅覆盖数字/字母/常用符号、标准字重;中文/艺术字不支持(双端一致) |
| Xlib 手绘观感简朴 | 接受;换取零依赖。后续可做扁平化配色微调,不引入主题库 |
| 无桌面/headless ARM 设备 | 不在本工具范围(GUI 程序);如有需求,后续可选 `--headless 任务.csv` 纯 CLI 模式(复用引擎,XTest 连远程 DISPLAY) |
